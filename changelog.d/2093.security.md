- **Symmetric JWK secrets outside JSON are redacted (#2093).** A symmetric key written as Python keyword arguments (`JWK(...)`, `dict(...)`) or as a YAML mapping had no braces for the JWK scan to read, so its `k` passed the telemetry redactor, the public-reply gate and the secrets audit. Blank and comment-only lines do not cut the block or separate an explicit YAML key from its value indicator; a standalone `?` uses its parent indentation through tag, anchor and block-scalar headers, including separate property lines and sequence items. Escaped physical continuations in `oct` and scalar aliases supplying the `kty` key (including tagged definitions) open the same block. A single comment-aware quote-context pass preserves complete JSON member names and string context even when a window starts inside a long string. Every value in the block is masked while member names and JSON structure are preserved; escapes inside values are masked too. Aliases throughout a document with an oct trigger and possible YAML merge syntax or tags seed anchor lookup, covering YAML merge consumers outside the original line/indentation window and merge chains of arbitrary depth. Aliased anchors mask every value from their definition to the end of their YAML document, with every physical line break recognized by the audit (the `str.splitlines()` model) also recognized by lookahead, masking and document boundaries, so a suppression marker applies only to its own line. This deliberately masks later values in the same document. Objects the JSON scan already decides keep its output exactly, while an oct type in an anchored JSON-style flow mapping can still protect later YAML merge consumers. The accepted over-redaction and remaining limits are documented in `telemetry/oct_blocks.py`. Single-quoted token decoding reads AST constants directly, avoiding recursive evaluator closure cycles that exceeded the unchanged peak-memory bound on supported Python 3.14.4.
