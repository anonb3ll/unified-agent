- **Stall detection now covers the Pi and agy-interactive backends, a quick
  clean exit can no longer be lost at spawn, and a duplicate node receipt
  cannot close a run it no longer owns (#1950).** Pi and interactive agy runs
  that write no output for `UA_EXECUTOR_STALL_TIMEOUT_S` are stopped and
  retried with backoff, like every other backend since #1916. Stopping one
  now kills its whole process group, tool descendants included, with a
  SIGTERM grace before SIGKILL. When that kill cannot be confirmed, the
  result says so (`cleanup_confirmed: false`) with the group to inspect, and
  the Active Executor holds the task as blocked instead of retrying it next
  to a possible survivor. A Pi descendant still writing after Pi exits, or
  after Pi's `agent_end`, is left to finish within the stall and wall-clock
  budget; one that goes silent is stalled and killed, and the run reports a
  timeout, not success. Partial stdout writes count as progress before a
  newline arrives. Pi and every pexpect exit report unconfirmed group
  cleanup, including prompt failure, approval denial and EOF; a surviving
  pipe holder cannot prevent the Pi runner from returning that result. The
  detached dispatch supervisor starts the CLI behind a start gate and
  releases it only after the child's pid is recorded and handed to the
  launching process, so no work runs, or finishes unobserved, before the pid
  is known; if the launching process gives up first, the CLI never starts. A
  node receipt only closes the run whose current evidence names its item and
  only while that run is live. That check is part of the same database write
  that closes the run, so a late or duplicate receipt for an earlier item no
  longer fails a resumed run, confirms a cancellation meant for its new item,
  or re-transitions a run the lease reconciler already handed back.
