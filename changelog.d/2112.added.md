- **Device acceptance before real work (#2112).** A harmless, no-model
  acceptance job checks a newly enrolled ua-node end to end: launch, progress,
  a receipt whose output digest the hub verifies, a hub cancel that the device
  confirms it honoured, and refusal of a revoked registration. Every node
  advertises the built-in `acceptance` backend. Start and read a run with
  `coordination_manage` (`node_acceptance_start`, `node_acceptance_evaluate`,
  `node_acceptance_status`), `POST /api/action/node-acceptance` or
  `GET /api/nodes/acceptance`. The result appears in `/api/nodes` and in the
  new `fleet_node_acceptance` doctor row. `UA_NODE_REQUIRE_ACCEPTANCE=1`
  (default on for public hosted mode, off locally) holds all other work at
  enqueue and claim time until independent operator attestation of the exact
  diagnostic run. Diagnostic events and digest are node self-report and alone
  cannot promote a device. Atomic starts, terminal timeout, periodic cleanup,
  ordered progress and hub-observed cancel relay prevent stale or overlapping
  diagnostics. A node whose
  agent is in `UA_REVOKED_AGENTS` is now refused on every node call.
