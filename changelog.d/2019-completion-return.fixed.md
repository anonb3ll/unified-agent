- **Completion notices on the `messages` surface follow-ups from the PR #1146 review (#2019).** A recorded duplicate under the notice id counts as delivered only when it has the notice's recipient, conversation, task and id; otherwise the row is skipped. A refusal by the conversation handoff authority is a terminal skip with its reason, not a failed send retried until abandoned, and a task that changes status during the send is not counted as an attempt. The pre-send check also refuses a row superseded since its claim, so a reopen and re-close no longer sends the old notice and then the new one. `agent.conversation.handoff` events are kept by event pruning, since they authorize those notices.
