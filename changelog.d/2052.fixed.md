- **The audit-lock timeout test no longer flakes on a loaded host (#2052, #2023).**
  `test_audit_lock_timeout_does_not_mistake_another_publishers_lock_for_ours`
  shadows the helper's retry `sleep` and keeps a 120 s timeout only as a hang
  guard, so a slow review host no longer hits `subprocess.TimeoutExpired`. It
  pins the exact retry schedule, so a blocking or changed retry sleep still
  fails, and still checks that another publisher's lock and pointer are left
  untouched.
