- **Control Center v2 hub operations (task #2480).** `plan_manage` gains `step_add`, `step_edit`, `step_remove`, `step_reorder` and `edit` (title and description, kept in the plan's `goal`), exposed exactly where `plan_update` is; step ids and dependencies are remapped together and claimed or done steps are never touched. `goal_manage` gains `edit`, `unlink`, `close` and `reopen`. New routes: one per plan structure and goal action, `POST /api/action/session/operator-end` (the operator ends another identity's session through the new `session.operator_end` platform writer, ledgered with the owner and reason), `GET /api/routines` with each routine's next run and recent runs, routine add, pause, resume and an operator "Run now" that can fire a scheduled routine with an `Idempotency-Key`, and `POST /api/action/langgraph/run` for the governed workflow, run under a registered session of the signed-in identity. Shapes are in `docs/control-center-api.md`.
  - **Deploy note (schema).** Additive migrations, run by `init_db` on start, no `SCHEMA_VERSION` bump: `plans.revision` and `goals.revision` (`INTEGER NOT NULL DEFAULT 0`; existing rows start at revision 0) with `AFTER UPDATE` triggers `plans_revision_bump` and `goals_revision_bump` that advance the counter on every update that does not set it; and `agent_sessions.operator_ended_by` (nullable `TEXT`, write-once marker of an operator-ended session). Running them again is harmless. Control Center "Run now" receipts are stored in `idempotency_keys` (tool `cc_routine_run`) and pruned after 7 days.
