- **An `oth` array cut off in a log excerpt no longer turns later records into key material.** Inside an RSA key's `oth` entries only `r`, `d` and `t` (and the other private names) are private, as RFC 7518 defines them. An unclosed `"oth": [` in a tool output used to make every later object an entry, so ordinary record fields (`type`, `id`, `turn_id`) were reported as JWK private members and masked. A cut-off entry's own `r`, `d` and `t` stay private, and a later object with its own `kty` is judged by that type, so an EC key after an untyped cut-off array no longer leaks its `d` through the redactors.
