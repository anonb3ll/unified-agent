- **A vendor's own detached signature no longer fails the security gate (#2419).**
  `SECRETS-KEY` reported the Claude Code client's signed policy file
  (`policy-limits.json.signature.json`) as a `JSON web token committed in source`
  at HIGH, and because the accepted-risk baseline is keyed by value hash, every
  time the client re-signed the document the gate went red again with nothing an
  operator could act on. A file in a dot-directory outside every git work tree,
  whose name ends in `.signature.json`, whose signed document sits beside it, and
  whose content is exactly one JWT at any depth is now `low` with a message
  saying what it is. In a repo the same file stays HIGH, since a committer
  controls its name, sibling and shape. Every other shape — a vendor key, a JWK
  private member, an assigned literal, a second token — keeps its severity.
- **A rotated secret value gets a triage task even under `[accepted-risk]` (#2419).**
  The tag suppresses refiling by class while the gate reads the value-keyed
  baseline, so a value that rotated in a baselined file left the gate red with no
  owner. That group now refiles once; `baseline accept` on the new value quiets it.
