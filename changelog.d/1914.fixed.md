- **Memory writes no longer lose appends or hold the hub write lock through
  slow work (#1914).** Two agents appending to the same note at once both keep
  their blocks. A save computes the note's embedding before it takes the write
  lock, and rebuilds the index notes after its own write commits, from one pass
  over the tenant's notes, so a cold model load or a large memory store no
  longer stalls other writers. `memory_prune_candidates` and
  `recall_maintenance` skip soft-deleted notes. The consolidate apply step is
  tenant-fenced, refuses to re-point a note already superseded by another
  survivor, records who applied it, and refreshes the index notes, as its
  restore step now does too.
