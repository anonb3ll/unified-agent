- **Follow-ups to worktree cleanup, the nightly pass's view and node retire (#2196).**
  `cleanup_stale_worktrees` now reports `liveness_unknown: true` with its
  `note` and cause when the pre-removal process re-read fails, not only the
  first scan. Doctor's view of the scheduled sleep pass reads `service.env`
  and `settings.toml` from the `UA_HOME` that `sleep-pass.env` sets, as the
  pass itself does. Devices leaves out the host row of a retired node unless
  that host is also an active node. A node brought back with `node_unretire`
  counts as live again only after a fresh registration or heartbeat, for
  automatic selection, direct enqueue, session-credential checks, team seat
  picking and restore, node-bound agent status, Devices and the doctor's
  fleet rows alike; the stored heartbeat stays as last-seen history. A dispatch settings file or sidecar
  write that fails after its rename landed the file removes that file
  (identity-checked) instead of leaving it for the age sweep.
