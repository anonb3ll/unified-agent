- **Review reads are recorded against the head they were performed at
  (#2259).** The review pipeline kept its verdict only as prose — a
  `[review: approved @ ...]` note and a PR comment — so no gate could tell
  "a human approved this head" from "somebody read this tree". A new
  `review_reads` table holds one row per `(repo, number, head_sha, kind)` for a
  steward read, a policy verdict, a human Ledger resolution, or a delta read
  that names the head it moved from. The release preflight consults these rows
  under the narrow head-moved rule.
- **A read record can no longer lie about how much was read (#2259).** The
  `for_pr` listing defaulted to a 50-row page, so the newest read of an older
  ancestor would simply not come back and read as "never read"; it now returns
  every row unless the caller asks for a page, pages by keyset on `(created_at,
  id)` without duplicating or shifting rows mid-walk, and `count_for_pr` lets a
  caller prove its walk was complete. `record()` also refuses a `files` value
  that is not a list of non-empty paths of at most 500 characters (at most 2000
  of them) and collapses repeats, instead of storing whatever it was handed.
  Reads now go through `storage.connect_read_only()`, so the gate cannot write.
- **The preflight now holds a red-tier head that moved after the review
  (the operator, 2026-10-31).** `review_head_gate` is the rule the operator chose: a head
  that moved after a recorded read passes when the delta touches nothing
  red-tier, and is held when it does and no delta read naming those files was
  recorded. It reads the canonical `RED_TIER_PATTERNS` from `cycle_eligibility`,
  a rebase that leaves every recorded read behind fails closed, and an
  unrecorded PR is not refused for being unrecorded — the Ledger approval bound
  to the exact head remains that authority. The preflight result now carries
  `review_head` with the verdict it used.
