- **Completion return (#1751).** A task created from a Slack thread now reports
  back in that thread when it moves to done, blocked or cancelled, whichever
  path made the change: `task_update`, the merge closeout, close-on-merge, the
  merge orchestrator or the reviewer auto-close. The origin comes from the
  signed Slack event, and the notice is queued in the same transaction as the
  status change. The drain (after commit, at start-up, on queue-hygiene passes
  that send notifications) coalesces, retries a failed send a bounded number
  of times, skips rows in backoff so they cannot starve new ones, and never
  resends. A notice not delivered within 24 hours expires unsent, and a Slack
  slot stuck after ten deferrals is abandoned. The message carries only the
  task id, a neutralised title (format and bidirectional characters removed),
  the status, an `evidence_ref` that is a commit SHA or an https URL (a link
  only for github.com or the `UA_PUBLIC_URL` host, otherwise shown as code)
  and a Control Center link. Slack delivery is at most once; Zulip delivery is
  at least once. Zulip origins have a delivery path but no creation path.
  Follow-up: the Control Center conversation handoff (#1426) should call
  `completion_return.record_origin` and wire a sender for the `messages`
  surface.
