- **Background LLM calls now prefer a headless Claude subscription session,
  then OpenRouter (#2025).** `llm_client`'s default chain is
  `claude_cli -> openrouter`. Local Ollama and the Google AI Studio leg are no
  longer in it (the Ollama helper and `gemini_ask` still work when called
  explicitly). The new `claude_cli` leg runs the Claude Code CLI as
  `claude -p --model claude-haiku-5-5` on the logged-in subscription only: it
  first checks `claude auth status` for a claude.ai login and that
  `claude --help` lists `--safe-mode` and `--permission-prompts`, and
  otherwise falls through, so it never bills an API key. The CLI runs in safe
  mode with no tools, MCP servers, hooks, skills or settings, in a private
  directory under the hub's data home, with an allowlisted environment, the
  prompt on stdin and the system prompt in a private file; its whole process
  group is killed when each run ends. The `openrouter` leg uses the pinned
  model `deepseek/deepseek-v4.1-flash` unless `UA_OPENROUTER_MODEL` names
  another. `pi_run_task` is now pinned to the `openai-codex` subscription
  provider. The nightly sleep pass needs the `claude` CLI logged in on the hub
  and `OPENROUTER_API_KEY` in `sleep-pass.env` instead of `GEMINI_API_KEY`.
  `system_doctor`'s `llm_provider_chain` row reports the CLI leg's login
  method from `claude auth status`, shows it down for a CLI too old for those
  flags, and never runs a completion.
  The `openrouter` and `subscription_pool` legs now check the reply's own
  `model` field. A reply naming a model other than the requested one (a
  dated `<id>-YYYYMMDD` snapshot still counts, as do the native and
  OpenRouter spellings of a Claude id) fails the leg with `model mismatch`,
  and so does a pinned reply naming no model. The usage ledger records the
  model the provider reported. A reply the leg rejects, including a Claude CLI
  completion that fails the schema or the model check, is still recorded once
  when it reports token usage, so a later paid fallback cannot hide it.
  `llm_provider_chain` also judges a memory pin in the hub's environment
  (`UA_MEMORY_PROVIDER`) as its own route and reports DEGRADED when the
  pinned leg is unusable, or MISCONFIGURED when the memory settings are
  invalid.
