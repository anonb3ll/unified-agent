- **Blanket-permission harness flags need a verified sandbox (#1948).**
  Copilot `--allow-all-tools`/`--allow-all`, Cursor `--trust`/`--force` and Agy
  `--dangerously-skip-permissions` are now attached only together with the
  harness's own sandbox switch (`--sandbox`, `--sandbox enabled`, `--sandbox`)
  and only after a host sandbox probe passes (`bwrap` on Linux, `sandbox-exec`
  on macOS). Otherwise approved dispatch and the executor refuse the launch with
  `harness_sandbox_unavailable:<backend>`. Agy without skip-permissions keeps
  its supervised mode. The `agy-interactive` tmux fallback now runs on a private
  tmux server started from the allowlisted child environment instead of the
  user's default server.
  A posture also requires the harness's own sandbox bypass to be verifiably
  off: Copilot needs `"sandbox": {"allowBypass": false}` in the child user
  settings selected by its scrubbed launch environment, never the parent
  config or unsupported repository overrides. The same checked environment
  reaches dispatch and executor children. The installed launch binary must
  confirm the effective value with a bounded local config query, catching
  whole-file schema errors that would otherwise restore Copilot defaults.
  Agy skip-permissions launches are
  refused (agy exposes no setting
  to disable `BypassSandbox`), and Cursor `--force` is refused. The host probe
  accepts only a real permission denial and never caches a failure.
