- **Redaction and completion-notice repairs from the integration review (#2007).** An unterminated PGP key or a PuTTY key whose header field holds `<`, `&`, `\` or a quote (`Comment: <user@example.invalid>`) is now removed whole; the scan stopped at that character and left the key body, in telemetry and in gcloud metadata scrubbing alike. A PuTTY key with no MAC line loses its short last private line even when prose follows, while a prose word after a full PEM line is kept. A JWK held as a structured dict in telemetry metadata has its private members withheld. The JWK scan stays linear on text cut at a backslash and on many small keys (40 KB had taken 9 s). A long camel-case value under a JWK member name outside any JWK is kept, and a URL scheme of 33 or more characters no longer hides its userinfo password. Message ids starting `completion-return-` are reserved for completion notices, so a public send can no longer take a notice's id first and block it.
- **Redaction fails closed on ambiguous key text (#2007).** A header field whose value only looks like an escaped line break (`Comment: C:\new-key` in raw text, or its JSON encoding) no longer ends the private-key scan before the key body. Once a JWK's `kty` makes a member private, its whole value is redacted, whatever its alphabet and even when the excerpt is cut off before the closing quote; an RSA multi-prime key's `oth` primes are redacted in text and withheld in telemetry metadata. Escaped member names (`\u006fth`) keep their meaning, and a JWK inside a Python triple-quoted string is found.
- **Private keys are redacted structurally (#2007).** From a private-key opener (`BEGIN … PRIVATE KEY`, a PGP private key block, or a PuTTY key file header), everything through a later END line or PuTTY `Private-MAC` line is removed, whatever lies between; with no closing line, everything to the end of the string that holds the opener, or in raw text to the end of the text. No header value can end a key early: an opener counts as inside a string only when a quote directly precedes it (an apostrophe in prose never does), and a PuTTY `Private-MAC` line closes a key only at the start of a line after its `Private-Lines`. A JWK private member whose value is not one plain string (an implicit concatenation, a prefixed string, an array) is removed as a whole expression, every private member inside an encoded JWK is reported, unquoted JavaScript member names are read, and an RSA key's `oth` value is taken whole when it is not a plain array.
