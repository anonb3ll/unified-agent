- **Forwarded-header trust is fail-closed and per-listener (#1892).** The HTTP
  hub ran uvicorn with `proxy_headers=True` and `forwarded_allow_ips=127.0.0.1`,
  so any process on the hub host could send `X-Forwarded-For` and pass device
  provenance (#1250) and the session-credential device check (#1744) as an
  arbitrary tailnet node. `scope["client"]` is now the real socket peer unless
  trust is explicitly configured: `UA_HTTP_PROXY_SOCKET` binds a second,
  owner-only (`0600`) Unix listener where forwarded headers are honoured — the
  path a trusted proxy such as Tailscale Serve is pointed at — and
  `UA_HTTP_PROXY_HEADERS=1` with `UA_HTTP_FORWARDED_ALLOW_IPS` restores the old
  connecting-IP trust on the TCP listener as a documented escape hatch. On
  the socket listener the rightmost untrusted `X-Forwarded-For` hop wins and
  `Host` is restored from the proxy's own `X-Forwarded-Host` (a Serve `unix:`
  backend sends `Host: localhost`), so the `UA_HTTP_PUBLIC_HOSTS` slice and
  OAuth host checks keep working; a comma-separated or malformed value is
  ignored. The socket's parent directory must be hub-owned and not group- or
  world-writable or the hub refuses to bind. The Control Center session
  cookie's `Secure` flag now follows the trusted request scheme rather than a
  raw `X-Forwarded-Proto` header. tailscaled's `Tailscale-Funnel-Request`
  marker — stripped from clients and re-emitted only for Funnel connections —
  is now authoritative for the public/private boundary: a request carrying it
  gets the `UA_HTTP_PUBLIC_HOSTS` slice, refused session credentials and
  pinned OAuth consent whatever `Host`/`X-Forwarded-Host` claims (Funnel's
  TLS selects on SNI, so `Host: localhost` was spoofable), on every listener,
  which also closes the same hole on the TCP-proxy forward. Deploy note
  (required —
  merging without it breaks node flows that resolve the tailnet peer through
  the HTTPS serve path): see
  `docs/mac-hub-topology.md` → *Forwarded-header trust and Tailscale Serve*.
