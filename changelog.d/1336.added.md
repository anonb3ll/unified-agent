- **MCP gateway, slice 1 (#1336).** A new `mcp_gateway` tool lets the hub call a
  configured downstream MCP server with a hub-held credential, so a harness can
  reach gbrain through the hub entry alone. Off by default (`UA_MCP_GATEWAY`).
  Servers come only from `UA_MCP_GATEWAY_SERVERS`; slice 1 fronts gbrain's
  read-only tools under a code-owned cap that config can only narrow. The bearer
  is a managed secret (consumer `mcp_gateway`) and never leaves the hub; a
  reflecting server's echo of it is redacted from results and client logs.
  The host is resolved once, every address must fit the URL's loopback,
  tailnet or public scope, and the connection is pinned to that address.
  Calls refuse redirects and compressed bodies, bound every response body
  before parsing (1 MB each, 4 MB per call), have a 30 s budget, label results
  untrusted, and record exactly one evidence event with an argument hash. Exposed to the
  steward and chief-of-staff profiles and the `connectors` toolset;
  `system_doctor` gains an `mcp_gateway` row.
- **MCP gateway, slice 2 (#1336).** The gateway now fronts several downstream
  servers. `UA_MCP_GATEWAY_SERVERS` is a registry where each server has its own
  transport, managed secret and allow list, and a new bounded stdio transport
  reaches codebase-memory (a child per call with a minimal
  environment, byte-bounded stdout, and its process group killed afterwards).
  `mcp_gateway` gains `search_tools`, discovery covers every server, and rows use
  namespaced names such as `gbrain.search`, cached with a bounded TTL. Each tool
  is classified read or write in a code-owned catalog: an unknown tool fails
  closed, reads run the policy gate under `mcp_gateway.<server>.<tool>`, and a
  write must be named in `allow` and approved once per exact arguments. Evidence
  now names action, access and caller, and uses the hub's redacted digest.
  `system_doctor` reports each server's state separately, and `ua mcp-entry`
  prints the one-entry harness config without changing anything. A hard deadline
  and a per-server concurrency limit keep a stuck downstream from holding the hub.
