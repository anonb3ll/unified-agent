- **Merge and review gates no longer pass unreviewed or unclassified changes.** A task merge without a mission link now pins the worktree head before its validation gates, refuses when the head moved during them or differs from the head the reviewer classified, and merges that exact commit instead of the branch name; a failed `git pull` of a tracked `main` stops the merge. Renamed files count under both their old and new path in red-tier classification (`git diff --name-status` and the GitHub compare API), so renaming `safety.py` away is held. The reviewer holds a task for a human when its diff against `main` is empty or unreadable, instead of treating it as clean.
