- **Live-state resource reads fail clearly when the baseline is late (#1962).** A resource read used to wait `BASELINE_WAIT_S` (30 s) for the poller's startup baseline and then read anyway. A change that landed after such a read could be absorbed into the late baseline and never announced to subscribers. The read now fails with a "live state is not ready" resource error, so the client knows to retry. The operator guide and code comments now also state the one best-effort case: reads after three consecutive failed baselines.
