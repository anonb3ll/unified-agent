- **Worktree cleanup sees programs behind wrappers and shells; node status agrees after unretire (#2192).**
  The in-use check that keeps a stale worktree from removal now finds the
  program a process runs behind `env X=1` (and `env -S '<cmd>'`), `sudo`,
  `doas`, `nice`, `nohup`, `setsid`, `timeout` and `xargs`, after `find
  -exec`, and inside `sh|bash|zsh|dash|ksh|mksh|fish -c '<cmd>'` strings,
  past shell keywords (`while ...; do tool; done`, `time tool`, `{ tool; }`)
  and in backticks. Those strings are parsed with shlex, or split whole on
  operators and whitespace when too long or unparseable, and every bare word
  in them is also looked up on PATH, so shell syntax the parser does not
  model can only keep a worktree. A bare program name is resolved against the hub's own PATH
  when the process's PATH cannot be read, and PATH lookups are cached for
  one scan. A same-user process with other groups, another group id or extra
  capabilities is still skipped rather than making liveness unknown: systemd's
  `(sd-pam)` helper is one on every user session. The docs now say why, and
  why a partial `lsof` result is not yet treated as unknown on macOS. After
  `node_unretire`, Devices shows a node that has not beaten again as
  `offline`, as the agent list and routing do, instead of `unknown`.
  `node_live_beat` now raises on a `nodes` row read without
  `heartbeat_floor`, and the raw-heartbeat inventory test reads the syntax
  tree, so a wrapped, multi-line or aliased read cannot slip past it.
