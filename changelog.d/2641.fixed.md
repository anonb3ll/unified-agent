- **A review read is recorded per reader, so a second read no longer overwrites the first (#2641).** `review_reads` was keyed by `(repo, number, head_sha, kind)`, so a reader recording the same head and kind replaced the earlier row: on PR #1608 an independent steward read was silently reduced to one row naming the later reader. The table is now keyed by `(repo, number, head_sha, kind, reader)` — an existing table is rebuilt on startup with every row kept — the same reader re-recording a head still updates its own row, and the release gate's result and the merge receipt name every reader at the head. A read that did not pass also can no longer be erased by another reader's later pass at the same head; the same reader re-recording its own row still replaces its own verdict.
