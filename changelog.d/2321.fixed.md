- **A task built in a native checkout is held for review, not rejected for a missing worktree (#2321).** A claim that records `provisioning: native-required` leaves the task row's branch and worktree empty, so a review of its open PR used to write `[review: rejected] no git worktree found`. The no-worktree check now also takes the branch from the task row's `branch` column, or from the head of the open pull request named in `evidence_ref`. It trusts that head only when the pull request is open, comes from the task's own repository and not a fork, and the branch exists on origin. The task is then held for the merge decision with a `[review: held-no-checkout]` note, which never counts as a review that ran the gates. A task that already carries the false rejection is repaired the same way, including when `evidence_ref` gains an open pull request only after that rejection. Branch names are checked with `git check-ref-format --branch` (so `+` and `@` are accepted) after a leading `-` is refused. A gh error still produces the rejection.
