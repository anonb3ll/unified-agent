- **Generated vault notes no longer overwrite a note you locked (#2091).** The
  hub's own report writers (memory consolidation, sleep pass, skill-cluster
  proposals, harness-config proposals and merge failure reports) now honour
  frontmatter `locked: true`, the same guard `vault_write` applies. When the
  note they would replace is locked, they write the next free sibling
  (`<name>-2.md`) and report that path; the skill-cluster pass also reports the
  locked note as `locked_path`, and does not file a proposal again when the
  original or any sibling already holds it. The audit re-anchor still appends
  to the locked witness notes it creates (also after a BOM or CRLF edit), but
  refuses any other locked note at that day's path. Session
  learning proposals and structured exports no longer race: two writers can no
  longer both decide a proposal is unfiled, or both claim one export file name.
