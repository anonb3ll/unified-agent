- **`run_cmd` no longer runs a git alias or reads a credential file that the agent set up, and `fs_list` globs stay inside the read roots.** `git clone --config` and the global `--git-dir`/`--work-tree` options are checked like `-c`, a git subcommand that is not a built-in (a possible `alias.<name>=!cmd`) forces approval, and every `run_cmd` git call runs with `safe.bareRepository=explicit`, so a bare repository written with `fs_write` is never discovered. `uniq IN OUT` is treated as a write to `OUT`, and a write to any path inside `.git`, `.hg` or `.husky` (not only `hooks/`) forces approval. `cat`, `grep` and the other content readers refuse the secret-bearing files that `fs_read` refuses. `fs_list` rejects an absolute glob or one containing `..`, and drops entries that `fs_read` would refuse: hook directories, secret filenames and symlinks out of the read roots.
