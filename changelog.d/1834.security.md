- **Tenant isolation fences for tasks, approvals, idempotency receipts and
  init tokens (#1834).** Another organization's task, approval or
  idempotency key now behaves exactly like a missing one: it cannot be
  updated, claimed, listed, built, commented on, read, resolved or replayed,
  and its approval pass or denial never applies to your call. `unified-agent
  init --force` with inline `UA_AGENT_TOKENS` now rotates only this host's two
  bearers instead of removing every other agent's. The untenanted private hub
  behaves as before.
- **Review follow-ups (#1834).** LangGraph's pending-approval lookups return
  only your organization's request. Work products belong to the organization
  that submitted them, so identical submissions from two organizations stay
  separate and one cannot read or link approvals onto the other's. An
  idempotency key may not contain the U+001F separator used for scoped keys,
  and under a tenant a retry whose only receipt predates tenant scoping is
  refused (use a new key) instead of running the write a second time.
- Work products now store their submitting organization (`org_id`, filled
  from each row's submitted event on upgrade), so ownership survives event
  pruning. Autonomy approval lookups and LangGraph task revalidation are
  fenced by organization, and reusing a message id another organization
  already used returns the normal "already used" error.
