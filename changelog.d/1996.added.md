- `system_doctor` has a `tenant_consistency` row: every process that opens the
  store records the tenant it stamps in `$UA_HOME/tenant-beacons/`, and the row
  reports `DEGRADED`, naming the process, when one stamped a tenant other than
  the hub's in the last 24 hours (for example an executor started without
  `WORKOS_ORGANIZATION_ID`, whose rows the hub cannot see). A running process
  re-stamps its beacon every 10 minutes, even while it holds one connection
  open; a beacon dated in the future is ignored. The row reads the hub unit's
  data directory, or the hub default when the unit sets no `UA_HOME`. The
  deployment-modes guide now states that every process sharing a data
  directory must carry the hub's `UA_EDITION` and `WORKOS_ORGANIZATION_ID`
  (#1996).
