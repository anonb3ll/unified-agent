- **Contextual JWK private-member detection is shared by the public relay, telemetry and source audits (#2001).** A JWK's private members (`d`, `p`, `q`, `dp`, `dq`, `qi`, a symmetric `oct` key's `k`, and an RSA multi-prime key's `oth` primes) are detected by the object they belong to. Detection works in text, in multiline or encoded JSON, in key sets, in cut-off excerpts, under escaped member names and inside Python triple-quoted strings. A private member whose value is not one plain string (an implicit concatenation, a prefixed string, an array) is taken as the whole expression (an RSA key's `oth` too, when it is not a plain array), unquoted JavaScript member names are read, and an encoded JWK is exempt as a placeholder only when every private value in it is one. Public keys and unrelated `d`/`k` fields stay usable. Once a key's `kty` marks a member private, its whole value is withheld, whatever its alphabet, even when the excerpt ends before the closing quote. Telemetry metadata that holds a JWK as a structured dict now has its private members withheld too. The scan stays linear on text cut at a backslash and on many small keys. Source audits report JWK findings on the right line for any line ending, stay linear in the file size (as does the relay's finding deduplication), and exempt only values that are entirely a placeholder.
