- **Agent retirement (#2305).** Operators can retire an agent (`coordination_manage`
  `agent_retire` / `agent_unretire`, or `POST /api/agent-lifecycle`). Retire is
  refused while the agent holds `doing` claims; in one transaction it records the
  state, revokes the agent's `agent_tokens` rows and session credentials, then
  requests the same stops as pause. `resume` cannot undo it. A retired identity is
  refused at session-credential, node-queue (admission and claim, every backend),
  team-boot and Slack sites with a typed error, each refusal recorded as
  `lifecycle.refused`. Every transition reads, authorizes and appends in one write
  transaction, so a concurrent pause cannot overwrite a retirement. Every registered agent has a
  queryable owner of record (recorded owner, else its org office). New
  `system_doctor` row `retired_agent_credentials` flags a retired label that still
  holds a credential, including a bearer left in `UA_AGENT_TOKENS`.
