- **Evidence reports list the gateway denials a run caused (#2309).** A gateway
  deny already carried the request's episode (`acp:<item>` for a session
  credential) in `event_log.episode_id`; it now also carries `args_sha256`, the
  redacted digest of the denied call's arguments, and the `policy_unavailable`
  path passes the episode explicitly. Every `evidence_report` record gains a
  `denials` block (report schema 1.8): the denials bound to its runs, each with
  tool, rule, reason code and digest, never arguments. Its `status` is
  `recorded`, `partial` or `not-recorded`. `recorded`, the only status where an
  empty list means zero denials, needs every run bound and no unbound deny by
  any participating agent in the record's window (`unbound_in_window`), so a
  run that executed on a bearer token, before the stamp existed, or alongside
  unbound denials is never reported as clean. Historical rows are not
  backfilled.
