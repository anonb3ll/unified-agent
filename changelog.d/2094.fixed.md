- **The ledger re-anchor no longer appends to a note it did not write, and a vault export no longer leaves a partial file (#2094).** An unlocked note at the day's `Logs/audit-ledger-heads/` path that is not a re-anchor witness is now refused and left untouched, as a foreign locked note already was; the run fails with a message saying to move the note aside. Witnesses the re-anchor filed itself, including the early ones without `locked: true`, are still appended to. A witness whose body is no longer valid UTF-8 is refused with the same advice, instead of crashing the job with a traceback. A vault export (`export_data` with `write_to_vault`) is now written and fsynced to a hidden temp file, then published by hard link into the first free export name in `00 - Inbox/exports/`. A failure part-way removes only that temp file and reports the error, so no truncated CSV or JSON is left under an export name. A note that Obsidian Sync or an operator puts at an export name mid-export is never overwritten or deleted. On a filesystem without hard links the export falls back to an exclusive in-place write. It reports a possibly incomplete file rather than deleting it, and if another writer takes over the name mid-write it reports the export as not delivered instead of claiming success at that path.
