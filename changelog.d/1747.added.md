- **Task subtree holds (#1747).** `coordination_manage` gains `task_hold`
  (`pause`, `cancel`, `resume`, `restore`), `task_holds` and `task_hold_get`,
  with `GET`/`POST /api/tasks/holds` and `POST /api/tasks/holds/{id}/release`.
  A hold snapshots a root task's subtree; while it is active, new claims,
  moves into `doing`, dispatch and node dispatch on its members are refused
  with an error naming the hold, while a live renewal lets an in-flight run
  finish. `cancel` reuses `request_cancel` on members' live runs and
  `node_queue.cancel` on their node items. `restore` undoes only the hold's
  own cancel requests: a member whose cancelled run is still open is reported
  `pending` and keeps the hold active until a later restore, and a task is
  reopened only when its run acknowledged the cancel. Only the hold's creator
  or an operator may release it. `after_active_runs_finish` (pause only, and
  only while something is running) releases a hold once no member has live
  work. Every change is recorded on `agent.task.hold`. The Control Center
  shows a **Held** badge and hold and release controls, with a confirm step,
  in the task detail pane.
