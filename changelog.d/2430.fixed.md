- **The test-budget gate counts the pull request, not the base branch (#2430).**
  The `gates` job measured the checked-out `HEAD` (the pull request merged into
  the *current* base tip) against `pull_request.base.sha` (the base tip at the
  pull request's last synchronize), so every commit the base branch gained in
  between was credited to the pull request: #1481 changed 3 test files and added
  31 test functions, and was failed as 20 files and +73. The base is now the
  first parent of the pull-request merge commit this job checks out, read by a
  new `merge-parent` mode of `scripts/test_budget.py`, which is fail-closed: it
  refuses a revision that is not a two-parent merge instead of counting one
  commit's tests against its own parent, and refuses a `--pr-head` that is not
  one of those parents (the checkout is then not that pull request's merge).
  Both workflow copies carry it, and `tests/test_ci_workflow_parity.py` now pins
  the parent rule and the refusal. A stacked pull request still carries its
  stack, so the under-budget pull requests in a stack land first.
