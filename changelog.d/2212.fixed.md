- **A FIFO, socket or device in a scanned tree no longer hangs the security
  audit (#2212, #2217).** The scan read every name `os.walk` returned, so a FIFO
  (including one named `.git`, which `SKIP_DIRS` never covered) reached
  `read_bytes()` and blocked forever in `open()`, and a character device
  slipped past the size cap because it reports a size of 0. Every audit read
  or write of a scanned path now goes through one module that touches only
  regular files: scanned files, `.ua-audit-ignore`, the agent-settings,
  MCP-config and `.gitignore` reads in the repo rules, `--remediate` fixes,
  and the vault anchor scans, verifier and re-anchor writer. It checks the
  type on the path and again on the open descriptor, opens without blocking,
  and reads at most one byte past the cap. A remediation whose target is not
  a regular file is reported as `[AUTO-FIX-FAILED]`, and a re-anchor refuses
  a dated note that is not one and decides its lock from the bytes it already
  read. `note_is_locked` opens without blocking too, and reports a FIFO,
  socket or device at a note path as an unreadable lock instead of hanging.
  Non-regular names stay visible to the name-based repo rules, so a `.env`
  linked to `/dev/null` is still reported as exposed, but they no longer
  count toward the file cap.
