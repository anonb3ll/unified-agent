- **Table tenancy inventory (#1433).** `tenant_tables.py` classifies every
  SQLite table as partitioned, derived, accelerator or global. A new test
  fails when a table ships without a tenancy decision, including tables
  created through concatenated or formatted SQL, `ALTER TABLE ... RENAME TO`
  or a `.sql` file. Partitioned tables must carry an indexed `org_id`; tables
  still missing one are listed in ratchets that may only shrink against frozen
  baselines. No runtime behaviour changes.

- **A sentinel organization and one storage chokepoint for `org_id`, off by default (#1433).**
  `unified-agent db org-partition` reports, and with `UA_ORG_PARTITION=1 ... --apply` runs, a one-shot backfill of NULL `org_id` to a sentinel, backup first and all or nothing, with a tested `--downgrade`. On a store marked that way every connection stamps and filters `org_id` for the partitioned tables, and persistent triggers refuse another org's rows. Nothing changes on deploy, a single-org hub reads exactly as before, and multi-tenancy stays off. See `docs/architecture/tenancy.md`.
