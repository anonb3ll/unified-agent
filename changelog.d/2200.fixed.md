- **YAML RSA, EC and OKP JWKs are redacted (#2200).** A JSON Web Key written
  as YAML kept its private members: in a flow mapping the redactor typed a key
  only from a quoted type string, so an unquoted `RSA` or `EC` type masked
  nothing, and no rule read an asymmetric key written as a block mapping. The
  JSON scan now reads an unquoted plain-scalar type (RSA, EC, OKP or oct), and
  a new block-mapping scanner masks the private members (`d`, and an RSA key's
  `p`, `q`, `dp`, `dq`, `qi`, `oth`) of the typed mapping itself: members
  before or after the type, items of a key set, comments, CRLF and CR line
  endings, and multi-line plain, quoted and block-scalar values. Public
  members (`n`, `e`, `x`, `y`, `crv`, `kid`, `alg`, `use`) stay readable. The
  log redactor, the secrets audit and the public-reply gate all get the fix;
  JSON objects and the symmetric-key rule are unchanged.
  The same scanners now also follow YAML aliases (a private value written as
  an alias masks the anchored node it names), read alias keys and explicit
  keys as nodes (tags, verbatim tags and anchors skipped, names on the line
  below), read a flow type after properties, comments or line breaks, and
  read a block key inside a JavaScript template literal written with escaped
  line breaks. A document that uses merge keys or alias keys together with a
  key type is masked conservatively: every private-named member in it.
  Every candidate definition of an aliased anchor is masked (an `&v` in a
  comment or in text cannot take the real one's place), an aliased flow
  collection is masked to its closing bracket, a repeated type masks the
  union of the private members of every type it names, a template key or type
  built with `${...}` is read as unknown, and a `%TAG` directive affects only
  the document it introduces.
  The conservative reading needs a YAML merge key in key position or a real
  alias key, and masks only mappings that take part in merging or aliasing,
  so Python, JavaScript, shell and C source is never read that way.
  Explicit, flow-explicit, quoted and tagged merge keys count as merges again
  (a quoted `<<` too, as libyaml and Psych merge on it), an anchored sequence
  item or lone anchor line marks the mapping below it, and a template literal
  with an interpolated key beside a key type or a private name is masked.
  An anchor glued to a flow indicator or on the line before a flow node, and a
  flow merge key glued to its value, are read as such. An unexpected error in
  the key scan now masks the whole text instead of escaping to the caller.
  Comments between an anchor or a flow separator and the node or merge key
  that follows, and anchor names of any length, no longer hide a merge.
  Comments follow YAML's rule everywhere: a `#` inside a quoted key is not a
  comment, and a `#` glued to a flow indicator or closing quote is one.
  Every YAML comment decision now comes from one lexer that reads the text as
  YAML once, checked against PyYAML's scanner: a quote or `#` inside a plain
  scalar, a comment glued to a closed quote, and an apostrophe inside a tag
  are read as YAML reads them, and a flow mapping YAML types is masked even
  where the object scan reads the same braces differently.
  The object scan's reading and YAML's now count as different wherever that
  scan can swallow a member YAML keeps: an unclosed quote, a backtick, `/*`,
  `//` or `/` in a plain scalar, a doubled single quote, or a quote glued to a
  quoted scalar. Private-named keys inside such a typed flow mapping are masked
  even where the two readings disagree about where a member starts. A `?`
  before a tag or anchor in a flow mapping keeps its key, a block scalar's
  `|N`/`>N` indentation indicator sets its content indent as YAML does, and a
  key line dedented to no open mapping keeps the types of the mappings it
  closed.
  A private member whose value is only node properties (`d: !!seq`, `d: &a`)
  keeps a compact sequence at its own column as its value, a `kty:` whose
  type sits below a line of node properties still types its mapping, and a
  closed quoted private value keeps its trailing comment.
  Merge keys, alias keys and alias values inside a JSON object whose type is
  quoted are now followed too (a nested mapping that merges a typed anchor, a
  `*n` key naming `d` or an oct key's `k`, a `d` aliasing a value anchored in
  the same object), a long run of private-named keys in one typed flow
  mapping is swept in linear time, and a member found in a later YAML
  document no longer hides an earlier document's private member from the
  secrets audit.
