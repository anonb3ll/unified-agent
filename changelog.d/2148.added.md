- **Cloud control plane on a GCP VM (#2148).** `deploy/gcp/control-plane/`
  stands up the production control-plane host in one scripted run: a daily
  snapshot schedule, a separate 50-100 GB data disk, an `e2-medium` VM with no
  external IP, provisioning over IAP SSH, and an acceptance check. It is
  dry-run by default and changes nothing without `--apply`. The VM runs the
  same image and env contract as the Railway staging deploy, with
  `UA_EXECUTION_LOCALITY=devices` pinned, the hub on loopback behind Tailscale
  Serve, and daily `memory.db` copies to the fleet GCS bucket. Runbook:
  `docs/deploy/gcp-control-plane.md`.
- **`UA_STATE_MOUNT_PATH` for the hub image.** Off Railway, the container
  refuses to start unless `UA_HOME` is on that path and the path is a real
  mount point, so a missing data disk or bind mount cannot put the database
  on the container's throwaway filesystem. Unset keeps the previous behaviour.
