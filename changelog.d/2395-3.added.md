- **Interrupted work is held and witnessed, never silently re-run (#2395).** When the lease reaper releases a claim whose owner is terminal or absent while the owner's self-pickup run is still open with no recorded end and no cancel request, the task goes to `blocked` (not `open`), gets `waiting_on` and an `[interrupted: run=… owner=… probe=…]` marker, and the same transaction appends one `run.interrupted` event on `agent.run.stalled` (deduplicated per run), which the supervisor's stall reconciler drains. Queue hygiene names it in its notification; the abandoned run record carries `to_status: blocked`. Resuming is an explicit claim. The owner probe also treats "every hub session of the owner is recorded ended after this claim, none open" as terminal, but only while the agent is not seen live and no node of it is online, so a claim whose interactive session died is released as interrupted work instead of being kept forever.
