- **The WIP defaults now say what the hub actually enforces (#2759).** Production
  ran `UA_AGENT_WIP_MAX=20` while the docs, the tests and most task notes said
  2, so every queue note quoting "refused at 2" described a cap the fleet never
  ran. The documented default is now 20, the fleet soft cap defaults to 40 and
  the fleet hard cap to twice the soft cap (80), so the fleet warning no longer
  fires at the same claim as the per-agent refusal. `UA_FLEET_WIP_MAX` no longer
  borrows `UA_DISPATCH_MAX_LIVE_RUNS` for its default, and
  `UA_FLEET_WIP_HARD_MAX` now defaults to twice the soft cap instead of three
  times it. A deployment that sets either variable explicitly is unaffected.
  `system_doctor` gains a `wip_policy` capability that reports the effective
  per-agent cap, overrides, lane caps and both fleet caps, and degrades when the
  fleet ceiling does not sit above the per-agent cap.
