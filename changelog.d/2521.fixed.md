- Vault journal and vault write no longer report an I/O error that struck after the write began as an ordinary refusal. Such a failure (a full disk, a failed flush or close) now raises the typed `outcome_unknown` error, which the Control Center answers as 409 on the first answer as well as on every repeat of the `Idempotency-Key`, so a client is told the note may hold part of the write. An error before the note is opened stays a plain refusal; `vault_write` used to let it escape as an unhandled error.
