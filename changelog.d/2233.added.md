- **A test budget keeps the suite from growing back (#2233).** A new test file
  named after an issue number, or a test file over 1500 lines, now fails the
  suite; files that already broke either rule are grandfathered at a fixed
  ceiling, and that list may only shrink. On a pull request, CI's `gates` step
  counts the `def test*` definitions in the changed files under `tests/` and
  fails when more than 60 are added, unless a commit message ends with a
  `Test-Budget: <reason>` trailer. Unreadable input fails rather than passes,
  and so does a changed file the count cannot read reliably (a symlink,
  `__test__`, or a collection hook). It budgets syntactic definitions, not
  collected tests. The rules live in `scripts/test_budget.py`.
