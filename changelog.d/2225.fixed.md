- **The security audit checks what a commit will record, not only the working copy (#2225).** Inside a git work tree it snapshots the index before reading files. Each index blob is either proven identical to the working-copy bytes the audit scanned or fetched by object id and scanned at full severity. A secret whose working copy is cleaned, deleted or hidden (assume-unchanged, skip-worktree, a clean filter, a symlink, a replacement ref) no longer passes the pre-commit gate. Everything the commit adds relative to HEAD must be covered: a git failure or timeout, an index that changes during the audit, or more than 5000 such blobs fails the gate with a high `AUDIT-INDEX-INCOMPLETE` finding. Committed blobs equal to HEAD whose working copy was not read are scanned with the remaining budget, and a secret found there fails the gate too. When some are left unread (over the budget, over the size cap with no oversized working copy, or after a git failure there only), the report is marked truncated. A medium `AUDIT-INDEX-PARTIAL` finding gives the count and the reason instead of failing the gate. The audited root's own repository honours `GIT_INDEX_FILE`, `GIT_DIR` and `GIT_WORK_TREE`, resolved by asking git itself for the absolute binding from the caller's directory and used for every git call the audit makes. A `GIT_INDEX_FILE` that names a missing or unreadable file fails the gate rather than reading as an empty index. Nested repositories are found from their `.git` entry and read with their own repository. Every audit git call runs isolated from system, global and transient caller config, so URL rewrites cannot downgrade a tracked MCP credential, and with fsmonitor off. The binding answer is parsed strictly, so a newline in a path fails the gate instead of selecting another index. A persisted `core.worktree` is honoured. An explicit binding to another repository fails the gate. The MCP and agent-settings rules also judge staged blobs. A new staged blob over the 1 MB cap fails the gate unless its working copy holds the same bytes. Something staged after the hook's audit has finished is still committed unscanned; `docs/security.md` documents that limit and the CI backstop.
