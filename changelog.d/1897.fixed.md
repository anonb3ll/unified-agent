- **`system_doctor` no longer drives hub CPU (#1897).** The report cache is now
  stale-while-revalidate with single flight: a report younger than
  `UA_DOCTOR_CACHE_S` (default raised from 20 s to 120 s) is served as is, one
  younger than the new `UA_DOCTOR_MAX_STALE_S` (default 600 s) is served at once
  with `stale` and `refreshing` while exactly one background run replaces it,
  and only a cold start, a report past the bound, or `refresh=True` waits (a
  run that then fails raises rather than serve an older report). A failed
  background run keeps the last good report and adds `refresh_error`.
  The worktree survey, which ran four or five git processes per worktree and
  ran twice per doctor run plus once per attention or executor pane poll, is
  shared for the new `UA_WORKTREE_SURVEY_CACHE_S` (default 300 s); a reused
  survey's row names its survey time. `refresh=True` surveys once anew for both
  the row and the host census, and never shares a run that began before it
  asked. The Control Center Doctor pane shows the report's age, counting on a
  local clock between polls, the stale and refreshing states and any
  background failure; its Refresh button still forces a fresh run and no
  longer joins a poll already in flight.
