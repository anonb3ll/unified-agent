- **The Approval Ledger backs off when GitHub rate-limits it.** A 429, or a 403 carrying `Retry-After`, `x-ratelimit-remaining: 0` or GitHub's rate-limit message, starts a per-credential wait: the longer of `Retry-After` and `x-ratelimit-reset`, 60 s when neither is usable, at most one hour of elapsed time even after a wall-clock step. Malformed values are ignored. The wait is held in the process and in a locked shared state file that only extends it; a failed write or an unreadable file backs off instead of reopening the gate. While it runs, every send is refused unsent and the poll and fast path stop their pass, so nothing is published. Only a request that reached GitHub uses up a retry turn, so corrections resume in order after the window instead of every 120 s. A 403 without a rate-limit signal is still a permission error.
