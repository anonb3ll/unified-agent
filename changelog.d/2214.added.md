- **The memory semantic leg uses a bounded KNN (#2214, audit M5).**
  `memory_search` and `memory_save`'s dedup check used to ask sqlite-vec for
  `k = COUNT(*)` vectors, because filters run after the KNN cut. sqlite-vec
  refuses a `k` above 4096, so on a store past that size every search silently
  fell back to the per-row `cosine_similarity()` scan. `memory_knn.bounded_knn`
  now starts at `k = 64` and doubles until the cut is proven: the mirror is
  exhausted, the last row is below the similarity floor, or enough eligible
  notes are already in hand. Eligibility runs after each cut, and the per-row
  scan answers when 4096 rows cannot prove the cut, after three native
  queries, or right after the first one when no eligible note appears. In
  the worst case that is three native scans before the full scan, per mirror;
  the single-vector and chunk mirrors are budgeted separately. The semantic
  leg, ranking and dedup suggestions match the full scan. No tool parameter
  or schema changed.
