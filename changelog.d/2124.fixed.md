- **An explicit YAML key inside an encoded log string no longer hides a symmetric
  JWK's secret (#2124).** A YAML mapping that names its key type as a quoted
  explicit key (`? "kty"` with `: oct` on the next line) was masked in raw text
  but not once it sat inside a JSON log field, a `json.dumps` of the text or a
  Python `repr`: the log redactor, the public-relay gate and the secrets audit
  all left `k` in place. The decoded string's quoted key name is now read as a
  key of that string rather than as a child string, so its oct block is found
  and the whole encoded string is masked, reported and attributed to its own
  physical line. JSON stays JSON, a surrounding RSA or EC object keeps its type
  and public members, and text without a key type is unchanged.
  Past the decode bound (a fourth nested encoding and deeper), a string is
  flattened first (backslash runs; `\u`, `\u{...}`, `\U`, `\x`, octal and
  `\N{...}` escapes; CR, LF and CRLF alike; quotes and YAML continuations)
  and is masked whole when it then holds a key-type name and a private
  member name, either each followed by a separator, comment or line end, or
  both as whole tokens anywhere. A string still encoded after the bounded
  flattening rounds, or holding an escape the pass cannot decode, is masked
  whole without requiring a type hint, unless only an undecodable escape
  stopped it and no key-type or private member name sits in member position
  (an identifier label such as `\u{a:b}` stays public, as before). The bound
  itself is unchanged.
- Preserve literal backslashes in terminal field scalars already decoded
  within the three-layer budget, including public EC/RSA log records with
  Windows paths containing recognized escape letters, quotes, brackets or
  literal line data. The existing string reader now records successful
  decoding, and the member lexer distinguishes scalar data from uncertain
  encoded names and child documents without a path-character allowlist or
  type-hint gate. Embedded document syntax and unfinished encoding still fail
  closed. Multi-codepoint Unicode named sequences are treated as undecodable
  instead of raising an exception; unknown names remain conservative.
- Malformed quotes in encoded log excerpts no longer hide explicit YAML
  private JWK values. Decoded scanning and the bounded fallback now use the
  same child-ownership proof: unfinished, mispaired and invalid quoted text
  cannot separate a key type from private material, while complete inert
  child literals retain their scope, including formatted literals that reuse
  their quote inside a replacement field (`f'{'x'}'`). Existing decode and
  resource limits remain unchanged.
