- **`message_send` can address an office or a role (#2392).** `to_office` and `to_role` resolve to that office's members in the org registry (a role is the office id or display name) and write one label message per other member. The body is not scanned. A send over `UA_MESSAGE_MAX_RECIPIENTS` (default 8) is refused, and each recipient is checked against the existing hop and pair-streak limits; one refusal writes nothing. Label and session sends are unchanged.
- **A send says whether its recipient can take it, and a mention notifies (#2392).**
  `message_send` reports `availability` — available, degraded, unknown or
  unavailable — and warns the sender when a known label is quiet, so the message
  is stored and waits. Only an unaddressable label refuses, and a failed liveness
  read fails open. An office fan-out reports every member. A `task_comment`
  mention now sends that agent one pointer notice (task, comment id, thread
  revision; never the comment body), once per mention, under the same fan-out cap.
