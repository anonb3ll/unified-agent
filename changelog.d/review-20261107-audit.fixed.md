- **The LLM-code audit sees through import shapes that used to hide it.** `check_py_ast` reads the LLM SDK from the import nodes, so `import json, anthropic` and `from google import genai` turn the checks on, and an SDK name inside a string no longer does. Aliased modules and from-imports resolve (`import subprocess as sp`, `from subprocess import run as r`, `builtins.eval`). Import aliases stay within lexical scopes, with local parameters and bindings blocking inherited aliases; an unrelated function's import no longer creates false eval or shell findings elsewhere. Literal shell dictionaries use the last duplicate key's value, matching Python. Syntactic dangerous-call matches remain active alongside resolved aliases, so an unrelated function's local import cannot hide `os.system`/`os.popen` or `subprocess(..., shell=True)` calls elsewhere. Any truthy constant `shell=`, a literal `**{'shell': True}`, `subprocess.getoutput`/`getstatusoutput` and `asyncio.create_subprocess_shell` are flagged. A bug-worker verification gate that times out now fails that gate instead of killing the worker, so the attempt is recorded and the task released. The Codex backend's `git rev-parse --git-common-dir` probe is bounded to 30 seconds.
