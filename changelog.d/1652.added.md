- **Runs v0 projection (#1652).** `GET /api/runs` and `GET /api/runs/{run_id}`
  serve one uniform run row — `run_id`, `kind` (`dispatch` | `selfpickup` |
  `session`), `task_id`, `agent`, `status`, `outcome`, `started_at`,
  `ended_at`, `lease_expires_at`, `abandoned`, `abandon_reason` and `links`
  (platform URIs plus evidence-ledger refs) — folded read-only from
  `dispatch_runs`, the `agent.run.selfpickup` event channel and
  `agent_sessions`. The list paginates by a stable `(started_at, run_id)`
  cursor, honours `kind`/`agent`/`task_id`/`limit` filters, and applies the
  abandoned-on-read rule without writing: a lapsed self-pickup lease or stale
  session heartbeat reads `abandoned` while its record stays open. Tenant
  fencing follows each store (`org_id` on `event_log` and `agent_sessions`,
  the `task_id` join for `dispatch_runs`), so another org's runs are absent
  from the list and 404 from the detail. Session rows join their node dispatch
  items by `external_session_id`, an open self-pickup run reports the task's
  live lease rather than its claim-time snapshot after a renewal, and a
  `retryable` dispatch reads as an ended attempt. The route carries the run
  object reader's `dispatch_report_self` ceiling; the verified human operator
  passes it for the Control Center pane.
