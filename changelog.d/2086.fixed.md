- **Generated vault notes take the per-note lock (#2086).** The consolidation proposal, sleep-pass report, skill-cluster proposal, harness-config inbox proposal, merge failure report and audit ledger re-anchor now write under the same `note_write_lock` as `vault_write`, so none of them can land between another hub writer's lock check and write. The skill-cluster fingerprint check and the re-anchor's existing-snapshot read run under the lock, so a note filed while the writer waited is kept (or appended to) rather than replaced. Content is built before the lock is taken, and the sleep pass files its notes only after its read transaction closes, including a computed skill-cluster proposal when a later read fails. An unreadable existing skill-cluster proposal still fails the pass, and a report-file fallback now reports its own path instead of the vault path.
