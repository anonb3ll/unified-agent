- **A lost node claim response is reconciled, not followed by a second claim (#2136).**
  `unified-agent node` now publishes a durable claim-operation id before it
  claims, and after a dropped response it asks the hub for that operation's
  one recorded outcome (with a fresh signed proof) before claiming anything
  else. The hub settles each operation in the claiming transaction, so a
  delayed original cannot claim after reconciliation, and a recovered item
  runs only if it is still that attempt's live, uncancelled claim. A node that
  may already have started an item when it stopped holds for the operator
  instead of relaunching it. This is fail-closed recovery, not exactly-once
  execution.
