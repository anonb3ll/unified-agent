- **Operator audit baseline (#2323).** `unified-agent-audit baseline accept <root> --reason "..."`
  previews the current high and medium `SECRETS-KEY` findings under an agent-home
  root (paths and detectors, never values) and, on `--yes` or an interactive yes,
  records exactly that set by sha256 of each value with the detector, root-relative
  path, who, when and why, in `$UA_HOME/audit-baseline.json` (JSON Lines, 0600,
  appended under a lock, hash-chained, opened without following links and checked
  on the descriptor). `--path` narrows it; `baseline list` shows truncated hashes.
  `unified-agent-audit surfaces` (the steward audit cron) applies it by default and
  reports the accepted count; the plain `unified-agent-audit <path>` that CI, the
  hooks, local-gate and the bug worker run applies it only with `--baseline`. A file
  inside a git work tree is never accepted. New values, another detector or another
  file keep full severity; credential-store and permission rules are never
  downgraded; a damaged baseline is ignored with a warning. The baseline is trusted
  local operator configuration, not proof of review: a same-user process can
  rewrite it, and removal of trailing entries is not detectable.
- **Agent-log JWK findings name their cause (#2323).** In an agent log a JWK finding
  carried the first masked member's name on its JSONL line (`kty`, `value`,
  `command`) while a live private member or a decoded-payload token on the same
  line graded it high. A high finding now names the private member or the token
  shape; a non-private name alone is never high.
