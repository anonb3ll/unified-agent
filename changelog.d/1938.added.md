- **`ua` adds controlled execution (#1938).** `ua delegate start` creates a
  delegation through the hub's existing gates (spec standard, trust boundary,
  `delegate` approval) with an idempotency key that is written to a private
  local receipt before sending; the spec comes only from `--spec-file`, never an
  inline prompt flag. The hub now enforces that key: `delegation_manage`
  `create` takes `idempotency_key`, commits the delegation and its receipt
  together, replays a committed key without a second row or approval, refuses a
  concurrent or mismatched reuse as `conflict`, and `delegation_manage` `lookup`
  reads a receipt with no effect. `ua reconcile KEY [--retry]` resolves an
  unknown outcome from it. `--wait`, `ua delegate wait` and `ua run wait` are
  bounded and never cancel: a budget that ends exits 10 (`in_progress`) with a
  durable reference, an unknown outcome exits 11 and an uncommitted request 12.
  `ua delegate cancel` (claim-generation fence), `ua run cancel`/`resume`,
  `ua workflow list`/`run` and `ua events follow` (JSONL paged by the gap-free
  `after_seq` cursor, with a resumable cursor file and reconnection) complete
  the slice. CLI flags no longer accept abbreviations.
  A receipt that cannot be updated after the request was sent is reported as
  `receipt_not_updated` with the hub's outcome and key (a committed delegation
  still exits 0, with a warning), never as "nothing was sent"; waits and
  `events follow` start no read past their deadline.
