- **Direct node enqueue honours device freshness (#2110).** Queueing work for a
  ua-node whose heartbeat is not live used to be accepted silently, so the work
  launched whenever the device returned, possibly days later. Now the item is
  accepted only as visibly waiting, with a reason and a deadline
  (`UA_NODE_QUEUE_WAIT_S`, default one hour). After the deadline it fails with
  `waiting_expired_node_offline` instead of launching late, and a linked
  dispatch run fails with it. Direct enqueue and automatic node selection now
  share one liveness rule. Run-lease reclamation no longer cancels a waiting
  item or makes its run retryable before the wait deadline. A run close that
  fails at expiry is retried by later sweeps until it settles. Cancellation
  settles waiting items and their linked runs before claim-time bulk updates,
  with durable retry after a close failure or crash; cancelled work cannot
  become retryable on run-lease expiry. Legacy cancelled waits without a
  settlement marker are reconciled too. The HTTP hub
  runs the expiry sweep itself every `UA_NODE_WAIT_SWEEP_S` seconds (default
  60, `0` disables), even with dispatch off. A malformed setting stops the hub
  at start, and a node dispatch refuses it before consuming an approval.
