# Configuration

All settings are read from environment variables by `src/unified_agent/config.py`. Set
them in the host's MCP server config (`--env` for Claude Code, the `env` block for
Antigravity, or `Environment=` lines in the systemd unit for hub mode) — the process
reads them once at startup, so changes require a restart. A few process-composition
variables (`UA_COMPONENTS`) are read at import by their owning module rather than
through `config.py`; they are still listed here.

See [installation.md](installation.md) for how these are wired into each host, and
[security.md](security.md) for the safety implications of the sandbox-related variables.

## Topology configuration

No network address is compiled into the code. Every host, port, allowlist, hub
URL, and bearer token is an environment variable defaulting to loopback / empty /
unset. A default install runs `UA_TRANSPORT=stdio` and binds no socket at all;
opting into `UA_TRANSPORT=http` starts a hub listening on `127.0.0.1:8765` with
nothing else set. Reaching another machine is a matter of the variables below.

Agent **identity** is a separate matter: `UA_AGENT_LABELS` and `UA_EXECUTOR_AGENT`
compile empty. A fresh install does not inherit this fleet's names; set both
before running a closed roster or the Active Executor.

| Concern | Variable(s) | Default | Point at another machine |
|---|---|---|---|
| Hub bind address | `UA_HTTP_HOST`, `UA_HTTP_PORT` | `127.0.0.1:8765` | Leave `UA_HTTP_HOST` on loopback and publish the port over your tailnet with `tailscale serve --bg --tcp 8765 127.0.0.1:8765`. **Never bind `0.0.0.0`.** Binding `UA_HTTP_HOST` directly to a tailnet address also works but only with a non-empty `UA_HTTP_ALLOWED_HOSTS` (next row) — without it there is no `Host`-header check at all on a non-loopback bind. See [installation.md → Tailscale exposure](installation.md#tailscale-exposure). |
| Who may reach the hub | `UA_HTTP_ALLOWED_HOSTS`, `UA_HTTP_ALLOWED_ORIGINS` | hosts: empty; origins: `null` + the hub's own origin (see the row further down) | With `UA_HTTP_ALLOWED_HOSTS` empty, `server._http_settings()` passes no `transport_security` to FastMCP, which then auto-enables DNS-rebinding protection **only for a loopback bind**. Any non-loopback bind therefore needs an explicit list of every `Host:` a client sends, e.g. `myhost:*,myhost.<tailnet>.ts.net:*`; unlisted hosts then get HTTP 421. |
| Client → hub URL | `UA_HTTP_HUB_URL` | **Required for `Desktop_*` / `Laptop_*`;** `server_*` may use the local bind default | Full MCP endpoint of the intended hub, e.g. `http://100.x.y.z:8765/mcp`. Primary clients fail closed when this is unset; `UA_HTTP_HOST`/`UA_HTTP_PORT` only describe a local server bind. |
| MCP session idle timeout | `UA_MCP_SESSION_IDLE_TIMEOUT_S` | unset — SDK default, 1800s (30min) | A stateful streamable-HTTP session with no request in flight for this long is closed; a 24/7 client then sees `MCPError: Session not found` / 404 on its next call and must re-initialize. Set an integer number of seconds to raise it (task #1298), or `0` to disable the idle timeout entirely. Negative or non-numeric values raise `ValueError` at startup. |
| Hub shutdown grace | `UA_HTTP_GRACEFUL_SHUTDOWN_S` | `10` | Seconds the HTTP hub waits for open connections after SIGTERM before cancelling them and running its normal shutdown (task #1812). Long-lived MCP streams never close on their own, so without a bound launchd SIGKILLed the hub on every restart. Accepted range 1-25, so the shutdown that follows still fits inside the Mac hub plist's `ExitTimeOut` 30. |
| Agent identity ↔ token | `UA_AGENT_TOKENS`, `UA_ENFORCE_AUTH` | empty; auth **off** | Set `UA_ENFORCE_AUTH=1` plus `label:token` pairs (or a file path holding them) before exposing the hub beyond loopback. Keep the value in a mode-600 env file; never commit or vault it. |
| Known agent labels | `UA_AGENT_LABELS` | **empty** (open roster) | Colon-separated roster. Unset means any well-formed label is accepted; empty/garbage refs are still refused. Set this to close the roster so `delegate` / `message_send` reject typos. |
| Executor worker identity | `UA_EXECUTOR_AGENT`, `UA_EXECUTOR_TOKEN`, `UA_AGENT_BEARER_TOKEN` | unset (required to start the executor), no token | The label the Active Executor claims work as, plus its hub credential. Sample deploy units set a concrete label. |
| Desktop Control Center URL | `T3CODE_UA_CONTROL_CENTER_URL` (an unmerged 2026-08 T3 Code experiment; **not** read by this repo and not supported upstream) | `http://127.0.0.1:8765/ui` | Nothing to set. Open the hub's `/ui` URL in a browser, e.g. a hub reached over Tailscale. |

**Agent roster is topology-neutral.** `config.DEFAULT_AGENT_LABELS` and `UA_EXECUTOR_AGENT` compile empty: a third-party install that does not set `UA_AGENT_LABELS` / `UA_EXECUTOR_AGENT` does not inherit this fleet's names. The executor daemon refuses to start until `UA_EXECUTOR_AGENT` is set.

**Grok bots are cloud-hosted hub identities.** They reach the hub through
private tailnet routes or the authorized public HTTPS 443 Funnel (#2289).
`agent-cloud-coord` is chief of staff; `Laptop_Agent5` is the attended
on-device backup (same profile, not cloud-hosted). `agent-cloud-agent8` is
research. The other bot labels and their profiles are in
[architecture.md](architecture.md). Provisioned client credentials map to each
bot's label; interactive public OAuth grants remain pinned to `agent-server-agent8`
on the restricted `public` profile. Public ingress serves MCP and OAuth, not
the Control Center UI or general API. See [grok-bot-connector.md](grok-bot-connector.md)
and the fleet route map in `~/agent-workspace/docs/topology.md`.
`agent-grok` / `agent-laptop-agent8` may still exist
as attributed identities on the research profile; they skip task git
worktrees and are not dispatch spawn targets. On a closed roster, add the
labels you use to `UA_AGENT_LABELS`; do not mint tokens from this change.

The deploy scripts under `deploy/mac-hub/` and the sample systemd/launchd units
carry one operator's concrete tailnet addresses as shell defaults (`${MAC_HOST:-…}`)
and commented examples. Those are operator artifacts, not library code — copy and
edit them for your own hosts.

## Environment variables

| Variable | Default | Effect | Read by |
|---|---|---|---|
| `UA_WORKSPACE` | `~/.unified_agent/workspace` | Write and execute sandbox for `fs_write`, `run_cmd`, `git_*`, `python_lint_and_format`, and symbol-index tools. `fs_read` / `fs_list` / `fs_search` also resolve inside known `~/dev` project checkouts when given an absolute path. | `config.workspace_root()` |
| `UA_HOME` | `~/.unified_agent` | Data directory; holds `memory.db` (SQLite). A missing directory is created mode 0700, including under umask 0002 (`config.ensure_private_directory`); an existing directory is not rewritten by mkdir. Opening the store refuses a group- or world-writable parent (`chmod 700 <parent>`) rather than tightening a directory the operator made shared. After a successful open, an owned dedicated parent (neither group nor other write) is tightened to 0700; shared locations such as `/tmp` are never chmod'd to 0700. | `config.data_home()` / `config.db_path()` |
| `UA_BACKUP_DIR` | `$UA_HOME/backups` | Where `create_backup()` writes integrity-checked complete snapshots of `memory.db`, and where `system_doctor`'s `database_backup` check looks for them. Kept under `UA_HOME` by default so backups follow a relocated installation; point it at a separately-mounted or encrypted volume to survive loss of the disk holding the database. | `config.backup_dir()` |
| `UA_ORG_PARTITION` | unset | Set to `1` to permit `unified-agent db org-partition --apply`, the one-shot org_id sentinel backfill (task #1433). See [architecture/tenancy.md](architecture/tenancy.md#enabling-and-rolling-back). | `config.org_partition_enabled()` |
| `UA_SHELL_ALLOWLIST` | `ls cat head tail grep find wc sed awk git python3 uv pytest ruff diff sort uniq which echo date` | Colon-separated first-token allowlist for `run_cmd`. An unset or empty value keeps the default list; a value that names no program, such as `:`, denies every command. | `config.shell_allowlist()` |
| `UA_TRANSPORT` | `stdio` | `stdio` or `http`. Anything else raises `ValueError` at startup. | `config.transport()` |
| `UA_WEB_DIST_DIR` | packaged build (`unified_agent/_resources`), or `packages/web/dist` in a source checkout | Optional override: absolute path to a custom or development Control Center build. | `UA_HTTP_HOST` | `127.0.0.1` | Bind host for the streamable-HTTP hub transport. | `config.http_host()` |
| `UA_HTTP_PORT` | `8765` | Bind port for hub mode. Non-integer values raise `ValueError`. | `config.http_port()` |
| `UA_HTTP_ALLOWED_HOSTS` | empty | Comma-separated `Host:` header allowlist (entries may carry ports, e.g. `name:*`). Non-empty enables MCP SDK DNS-rebinding protection; **required** for any client that isn't literally `localhost` — without it the SDK answers non-localhost Host headers with HTTP 421. | `config.http_allowed_hosts()` |
| `UA_HTTP_PUBLIC_HOSTS` | empty | Colon-separated `Host:` values reachable from the public internet (Tailscale Funnel, task #859). A request with a matching Host is served `/mcp` + the OAuth endpoints only; `/ui`, `/api/*`, `/healthz` return 404 before auth. Must be a subset of `UA_HTTP_ALLOWED_HOSTS`. The same slice is forced whenever tailscaled's `Tailscale-Funnel-Request` marker is present (task #1892): the marker is stripped from clients and re-emitted only for Funnel traffic, so it overrides any `Host`/`X-Forwarded-Host` claim — including `localhost` — on every listener, configured or not. | `config.http_public_hosts()` |
| `UA_HTTP_PROXY_HEADERS` | off | `1`/`on`/`true`/`yes` makes the TCP listener honour `X-Forwarded-*` from peers matching `UA_HTTP_FORWARDED_ALLOW_IPS` (task #1892). Off, `scope["client"]` is always the real socket peer and no loopback process can claim a tailnet address. This restores the pre-#1892 implicit trust and is an escape hatch for a hub behind a local reverse proxy — any matching peer can assert any client address, so prefer `UA_HTTP_PROXY_SOCKET`. | `config.http_proxy_headers()` |
| `UA_HTTP_FORWARDED_ALLOW_IPS` | `127.0.0.1` | Comma-separated IPs/CIDRs (or `*`) whose `X-Forwarded-*` is honoured on the TCP listener. Inert unless `UA_HTTP_PROXY_HEADERS` is on. | `config.http_forwarded_allow_ips()` |
| `UA_HTTP_PROXY_SOCKET` | unset | Absolute path of a second, owner-only (`0600`) Unix listener that always honours `X-Forwarded-*` — the trusted ingress for a local reverse proxy such as Tailscale Serve (`tailscale serve unix:<path>`). The socket's parent directory must be hub-owned and not group- or world-writable (it is created `0700` when missing); the hub refuses to bind otherwise. On this listener only, `Host` is restored from the proxy's `X-Forwarded-Host` — a Serve `unix:` backend sends `Host: localhost` — so the `UA_HTTP_PUBLIC_HOSTS` slice, `UA_HTTP_ALLOWED_HOSTS` and OAuth host checks see the real host. Unset = no second listener and no trusted path. The TCP listener's trust is decided by `UA_HTTP_PROXY_HEADERS` alone, which never honours `X-Forwarded-Host`. | `config.http_trusted_proxy_socket()` |
| `UA_OPERATOR_TZ` | host zone | IANA timezone (e.g. `America/Indiana/Knox`) for operator-facing day windows: `task_list(local_day=...)` resolves "today" and `YYYY-MM-DD` in this zone. Storage stays UTC; only the window is local. An unknown zone is refused. | `config.operator_tz()` |

### Per-run model override (task #1153)

A task or delegation note may carry a line `[model: <id>]`. The Active Executor
and Control Center dispatch paths parse the last such marker and pass it to the
backend CLI (`--model` for Cursor, Codex, Agy, Claude, and Pi). Invalid ids warn
and fall through to the configured default. Unset envs + no marker keep each
backend's prior behaviour.

Control Center's Dispatch Studio selector writes this marker into the generated
spec; registry sessions and executor evidence attempts persist the resolved
model for display.

> **Note:** `UA_ALLOW_LOCAL_FETCH`, `UA_SANDBOX_ENABLED`, and `UA_SANDBOX_NETWORK` are
> boolean-shaped env vars whose code check is a strict string equality against `"1"` —
> any other value (including `"true"` or `"yes"`) is treated as unset/false.

### Memory ranking formula

Since task #1913, `memory_search` fuses per-leg ranks instead of summing raw
scores (`memory_ranking.py`):

```text
rrf            = sum over legs the note appears in of  w_leg / (k + rank_leg)
prior          = clamp((1 + 0.2 * tanh(p)) * age_discount, 0.8, 1.2)
p              = w_salience * 2 * (salience - 0.5) + w_feedback * feedback + w_vote * vote
combined_score = rrf * prior
```

| Variable | Default | Effect |
|---|---|---|
| `UA_MEMORY_RRF_K` | `60` | RRF smoothing constant `k`. |
| `UA_MEMORY_WEIGHT_FTS` | `1.0` (was 0.5) | Lexical leg weight (bm25 rank; AND hits ahead of OR-only hits). |
| `UA_MEMORY_WEIGHT_SEMANTIC` | `1.0` | Semantic leg weight (similarity rank). |
| `UA_MEMORY_WEIGHT_ENTITY` | `1.0` (was 0.6) | Entity leg weight (project/task/branch/agent/service matches). |
| `UA_MEMORY_WEIGHT_RECENCY` | `0.2` (was 0.3) | Recency leg weight (whole days since `updated_at`). |
| `UA_MEMORY_FTS_LIMIT` | `200` | Row cap on each FTS query. |
| `UA_MEMORY_FTS_OR_THRESHOLD` | `10` | Run the OR fallback when the AND query finds fewer notes than this. |
| `UA_MEMORY_SEMANTIC_MIN_SIMILARITY` | `0.65` | Cosine floor for the semantic leg, any query length. |
| `UA_MEMORY_SEMANTIC_TOP_K` | `50` | Semantic leg size. |
| `UA_MEMORY_WEIGHT_SALIENCE` | `0.5` | Salience weight in the prior; salience 0.5 is neutral. |
| `UA_MEMORY_WEIGHT_FEEDBACK` | `0.4` | Feedback weight in the prior; `feedback` is `tanh(ln(1+helpful) - 1.2 ln(1+not_helpful) - 0.8 ln(1+stale) - 1.5 ln(1+wrong))`. |
| `UA_MEMORY_WEIGHT_VOTE` | `0.35` | Upvote weight in the prior; `vote` is `recall_curation.vote_term(0, upvoted)`. |
| `UA_MEMORY_WEIGHT_ACCESS` | — | Deprecated and ignored: access counts no longer rank. |

`age_discount` is `1` until a note is older than `UA_MEMORY_DECAY_MONTHS`
(default 6), then `max(0.5, 0.95^(age_months - UA_MEMORY_DECAY_MONTHS))`. A
value of `0` or less disables the discount. A note is a candidate only if it is
an FTS hit, in the semantic leg, or matches a task or branch identifier. The
automatic recall count and `access_count` are recorded but never ranked.
`UA_MEMORY_RECENCY_HALF_LIFE_DAYS` now shapes only the reported `recency` value;
the recency leg ranks by age directly. Details
and the evaluation fixture are in
[memory-tasks-vault.md](memory-tasks-vault.md#search).

## Embedding model

`UA_EMBED_MODEL` selects the fastembed model for semantic memory and symbol vectors. The default is `BAAI/bge-small-en-v1.5`, fastembed's own `TextEmbedding` default, so an unset variable keeps today's vectors.

`UA_MEMORY_CHUNK_EMBEDDINGS` stores extra vectors for a note longer than about 2,000 characters (task #2182). The model reads 512 tokens, so a single vector describes only the opening of a long note. With the flag on, the note is also split into overlapping windows of about 400 tokens (1,600 characters, 320 characters of overlap, at most 16 windows) and search scores the note by the best of its single vector and those windows. Short notes stay on the one-vector path. Accepted values are `1`/`true`/`on`/`yes` and `0`/`false`/`off`/`no`. Unset or anything else uses the default, which is **on**. A 30-question LongMemEval sample (5 per type, seed 2145) rose from 26/30 to 27/30 strict recall@5 with the flag on, and no question scored worse; ingest on that sample took about four times as long. Set the variable to `0` to keep only the truncated vector. Deleting a note deletes its windows too. Superseding a note keeps them, so a historical search can still score the old text; default search skips superseded notes. Existing long notes are filled in the background after startup, in small batches, and only while the flag is on.

`get_embedding_model()` passes that id as `model_name`. New rows record it on `memory_embeddings.model` and `workspace_symbol_embeddings.model`. The migration adds the nullable column and does not rewrite existing blobs; rows from before the column stay `NULL`.

`system_doctor`'s `semantic_search` check is `MISCONFIGURED` when a stored model id differs from the current `UA_EMBED_MODEL`. Unlabeled legacy rows are not a mismatch. Changing the variable does not re-embed notes already stored.

### Messaging surfaces

Zulip is retired by default: `zulip_send_message` refuses every send unless
`UA_ZULIP_RETIRED` is `0`/`false`/`no`/`off`. While retired, no auto-reply or
digest reaches Zulip, so `UA_ZULIP_MAX_OUTBOUND_PER_HOUR` and
`UA_ZULIP_REPORT_AGENT` have no visible effect. `zulip_chat.maybe_reply` checks
retirement before it claims a message or calls the model, so `UA_ZULIP_CHAT=1`
on a retired hub generates no reply and costs nothing (task #1714; before
that, the model was called and the refused reply went uncounted by
`UA_ZULIP_CHAT_MAX_PER_HOUR`, which counts only replies with status `sent`).
